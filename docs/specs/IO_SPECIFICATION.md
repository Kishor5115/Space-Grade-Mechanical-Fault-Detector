# I/O Specification — Space-Grade Mechanical Fault Detector

> **SSCS Chipathon 2026 — Track B (Sensor Circuits) | Team B22 — Team Space Jam**

---

## 1. Overview

The chip's external interface consists of:
- A **sensor SPI bus** (slave-side connection to the IIS3DWB MEMS accelerometer)
- A **DRDY interrupt** line from the sensor
- A **mode-select** pin (`tmr_forward_en`)
- A **single digital output** (`fault_flag_out`) — the fault alarm
- Standard **clock and reset** pins

The output is **not analog** and **not SPI** — it is a **single active-high digital level** that latches on first fault detection and remains asserted until explicitly cleared via the internal APB register write. There is no separate host-facing SPI port within the current `top.v` boundary.

## 2. Pin Table

| Pin Name | Direction | Width | Level | Description |
|---|---|---|---|---|
| `clk` | Input | 1-bit | 5 V digital | System clock, 16 MHz (signed-off). All flip-flops are positive-edge triggered. |
| `sys_rst_n` | Input | 1-bit | 5 V digital | Active-low asynchronous reset. Asserts all FSMs to their idle/reset states simultaneously. |
| `c_miso` | Input | 1-bit | 5 V digital | SPI MISO: IIS3DWB → ASIC. Raw digital from sensor; passed through a 2-stage FF synchronizer (`ff_2_sync`) before entering the SPI FSM. |
| `c_csn` | Output | 1-bit | 5 V digital | SPI chip-select (active-low). Asserted by `spi_master` for each transaction. IIS3DWB requires CS to toggle between consecutive accesses. |
| `c_sclk` | Output | 1-bit | 5 V digital | SPI bit clock (Mode 3: idles high). Generated by `clk_divider` (DIV_LOG2=3, ÷8 of system clock). Held high when `c_csn` is deasserted. |
| `c_mosi` | Output | 1-bit | 5 V digital | SPI MOSI: ASIC → IIS3DWB. Drives boot write frames and read-command bytes. |
| `sensor_drdy` | Input | 1-bit | 5 V digital | Data-Ready interrupt from IIS3DWB `INT1` pin (async, active-high level). Synchronized to core clock before use. Fires once per sensor sample at 26.667 kHz after boot. |
| `tmr_forward_en` | Input | 1-bit | 5 V digital | Sample delivery mode select. **0** = Option A: samples accessible via local register poll only. **1** = Option B: additionally forward each sample into `tmr_reg_bank` over internal APB bus. Intended as a post-fab config fuse. Default (tie low) = Option A. |
| `fault_flag_out` | Output | 1-bit | 5 V digital | **System alarm output.** Active-high, sticky. Asserts when any (frequency bin, sensor axis) magnitude exceeds the programmed threshold within a 512-sample block. Remains asserted until cleared by a `cfg_fault_clear` APB write (CTRL register bit 1). |

## 3. Sensor SPI Bus — Detailed Protocol

### SPI Mode
- **SPI Mode 3** (CPOL=1, CPHA=1): clock idles high; data driven on falling edge, sampled on rising edge
- Reference: IIS3DWB datasheet DS12569 Rev 8, Section 3.2 / Figure 3

### Clock Rate
- System clock: 16 MHz (signed-off)
- SPI clock: system clock ÷ 8 = **2 MHz** (within IIS3DWB's 10 MHz maximum)

### Transaction Types

#### Type 1 — Boot Configuration Write (at power-on only)

At reset release, `spi_master` executes the following 4 write transactions **before** looking for any `sensor_drdy`:

```
Frame format (16-bit, MSb first):
  Bit 15       : R/W = 0 (write)
  Bits 14–8    : 7-bit register address (MSb first)
  Bits 7–0     : 8-bit write data (MSb first)

Boot write sequence:
  1. CTRL1_XL    (addr=0x10, data=0xA0)  — Enable accelerometer at 26.667 kHz ODR, FS=00
  2. FIFO_CTRL4  (addr=0x0A, data=0x00)  — FIFO bypass (no on-sensor buffering)
  3. CTRL3_C     (addr=0x12, data=0x04)  — IF_INC=1 (enable auto-increment burst reads)
  4. INT1_CTRL   (addr=0x0D, data=0x01)  — Route DRDY to INT1 pin
```

After all four writes complete, `spi_master` enters `IDLE` and waits for `sensor_drdy`.

#### Type 2 — Burst Read (once per sensor sample, triggered by DRDY)

```
Transaction format:
  Phase 1 — Command byte (8-bit, CS asserted):
    Bit 7      : R/W = 1 (read)
    Bits 6–0   : Address = 0x28 (OUTX_L_A — starting register for XYZ burst)
    → full byte = 0xA8

  Phase 2 — Data receive (48-bit, auto-increment, CS still asserted):
    Bytes received in order: OUTX_L, OUTX_H, OUTY_L, OUTY_H, OUTZ_L, OUTZ_H
    → bit shift register fills MSb-first per byte, earliest byte at top:
    s_data_out[47:32] = {OUTX_H, OUTX_L}   (X-axis, 16-bit signed)
    s_data_out[31:16] = {OUTY_H, OUTY_L}   (Y-axis, 16-bit signed)
    s_data_out[15:0]  = {OUTZ_H, OUTZ_L}   (Z-axis, 16-bit signed)
```

### SPI Data Format (IIS3DWB Output)

Each axis output is a **16-bit two's complement signed integer** (Q1.15):
- Range: −32768 to +32767
- Value at ±FS (±2g): ±32768 (±1.0 normalized)
- Sensitivity: 1 LSB = FS/32768

The `axis_sequencer` sign-extends each 16-bit value into the 24-bit Q8.15 datapath used by `goertzel_core` without any explicit conversion module — the sign-extension is a combinational bit-replicate in the `goertzel_core`'s input registration always block:
```verilog
x_q15_r <= {{(DATA_W-SAMPLE_W){x_n[SAMPLE_W-1]}}, x_n};
```

## 4. Fault Output — Detailed Specification

### `fault_flag_out`

| Property | Value |
|---|---|
| Signal type | **Digital, active-high, sticky level** |
| Width | 1-bit |
| Voltage | 5 V core + I/O (single supply; see Voltage Domain note) |
| Default state | Low (0) — no fault |
| Set condition | Any of the 9 (axis×bin) magnitudes exceeds `cfg_threshold` within a 512-sample block |
| Clear condition | Software write of `1` to CTRL register bit 1 (`cfg_fault_clear`) via the internal APB bus |
| Persistence | Remains high across multiple blocks until explicitly cleared; a second fault while already flagged does NOT update `fault_mag_latched` / `fault_axis_latched` |

## Voltage Domain and Sensor Interface

### As built

The chip is a **single supply domain**. The `slot_1x1` padring (`src/chip_top.sv`) ties the pad
cells' `DVDD`/`DVSS` to the same `VDD`/`VSS` nets that feed the core, so there is no separate I/O
rail and `info.yaml` correctly declares **one `power` pin and one `ground` pin**.

Signoff was performed at **5 V nominal** — corners `tt_025C_5v00`, `ss_125C_4v50`,
`ff_n40C_5v50`, i.e. 4.5 / 5.0 / 5.5 V (confirmed from the liberty `nom_voltage` fields). All pad
cells in use are the 5 V parts: `gf180mcu_fd_io__in_s` (clk), `in_c` (inputs),
`bi_24t` (outputs).

### The interface problem

The off-chip IIS3DWB is a **3.3 V-class part** (VDD 1.71–3.6 V, VDDIO 1.62–3.6 V). Driving it from
a 5 V rail breaks in both directions:

| Direction | Problem |
|---|---|
| ASIC → sensor (`c_csn`, `c_sclk`, `c_mosi`) | pads swing 0–5 V into pins rated ~3.6 V max — overstress |
| Sensor → ASIC (`c_miso`, `sensor_drdy`) | a 5 V CMOS input needs V<sub>IH</sub> ≈ 0.7 × V<sub>DD</sub> = 3.5 V; a 3.3 V driver does not reliably register as logic high. The Schmitt `clk` pad is worse still. |

### Resolution: keep the chip at 5 V, translate on the board

**gf180mcu ships no level-shifter cells** — none in `gf180mcu_fd_sc_mcu7t5v0`, none in
`gf180mcu_fd_io`. On-chip level shifting is not an available option, and a second supply domain
would require IO-ring break cells (`brk2`/`brk5`) plus an extra supply pad, which the fixed
shuttle padring does not provide.

**The shuttle pad ring is a 5 V ring, and this is not ours to change.** The padring instantiates
`gf180mcu_ws_io__dvdd` / `gf180mcu_ws_io__dvss` for all 18 power/ground pads, and those cells ship
**only** 5 V liberty views (`tt_025C_5v00`, `ss_125C_4v50`, `ff_n40C_5v50`) — there is no `3v30`
or `2v97` power-pad view in the fork. Powering that pad at 3.3 V would be running it off-spec with
no data to sign off against. (The *signal* pads do ship 3.3 V views, but the power delivery is what
fixes the ring voltage.) So although the standard cells themselves are rated 1.62–5.5 V, the
**correct and lowest-risk choice for this shuttle is to keep VDD = 5 V** — which is exactly what the
signed-off `chip_top.gds` was built and verified at. No silicon rework.

The voltage gap to the 3.3 V IIS3DWB is therefore closed **on the board**, which is how every prior
shuttle project handled it. The Integration track documentation frames the pad domain the same way:

> - The main voltage associated with all the I/O pads is 5V.
> - The gf180mcu D flavor allows to use both 3.3V and 5V/6V devices.

Board-level translation on all 12 sensor/host signals — e.g. a TXB0104-class auto-direction
translator for the SPI buses, 5 V on the ASIC side, 3.3 V on the sensor side. This is a ~$0.50 PCB
component, not a silicon change, and it does not affect `info.yaml` or the GDS.

### Action required before tape-out

1. **Keep VDD at 5 V.** No RTL, floorplan, pad-map or signoff change — the current
   `chip_top.gds` stands.
2. **Add board-level level translation** between the ASIC's 5 V SPI/host pads and the 3.3 V
   IIS3DWB when the evaluation board is designed. Bidirectional translator on
   `c_sclk`/`c_mosi`/`c_csn`/`c_miso`; the command-SPI and strap inputs (`cmd_*`,
   `tmr_forward_en`, `sensor_drdy`, `sys_rst_n`, `clk`) are driven by board logic that can be
   supplied at 5 V directly, or translated if the host is 3.3 V.
3. **Optional confirmation with the organisers:** that `slot_1x1` is energised at 5 V (expected,
   given the 5 V-only power pad). A 3.3 V ring would be the only thing that reopens this — and
   would itself require the organisers to supply 3.3 V power-pad views.

### ESD — and why secondary ESD does not apply here

Per the Integration documentation, **"All the I/O cells include ESD protections."** The digital pads
used by this design (`in_c`, `in_s`, `bi_24t`) carry their own primary protection.

**Secondary ESD** (`io_secondary_3p3` / `io_secondary_5p0` in
`resources/Integration/Chipathon2025_pads/`) is a series poly resistor plus a pair of clamp diodes
(`diode_pd2nw_03v3` / `diode_nd2ps_03v3`) inserted between an **analog** pad's primary
double-diode protection and a sensitive thin-oxide transistor gate — its ports are literally
`ASIG5V` → `ASIG3V3`. It exists because the 5 V analog pad's primary clamp alone still lets through
enough voltage to damage a 3.3 V device gate.

**This design has zero analog pins.** All 12 signals are digital and pass through digital pads with
built-in protection, so no secondary ESD structure is required and none is declared in `info.yaml`.
The two `analog[1:0]` pads that physically exist in `slot_1x1` are left unconnected at the
`chip_core` boundary (pure pass-through to the `asig_5p0` cells) and carry no signal from this
design.


> ⚠️ **These registers are NOT readable from outside the chip** — see
> [Read-back accessibility](#read-back-accessibility-in-silicon) below. They exist in
> `tmr_reg_bank` and are exercised by the testbenches through hierarchical access on the internal
> APB bus, but no chip-observable path to them exists.

`tmr_reg_bank` implements the following read-only fields:

| Register | Address | Field | Description |
|---|---|---|---|
| STATUS | 0x14 | bit 0 | `fault_flag` — mirrors `fault_flag_out` |
| FAULT_MAG | 0x18 | [31:0] | `fault_mag_latched` — magnitude value that triggered the fault |
| FAULT_BIN | 0x1C | [1:0] | `fault_bin_latched` — frequency bin index that triggered (0/1/2) |
| FAULT_BIN | 0x1C | [3:2] | `fault_axis_latched` — physical axis that triggered (0=X, 1=Y, 2=Z) |

### Read-back accessibility in silicon

**The only fault information observable off-chip is the single `fault_flag_out` bit.**

Both APB masters are hard-wired write-only, and there is no return pin:

```verilog
cmd_spi_slave.v:51        assign req_write     = 1'b1;  // this slave only ever writes
spi_apb_interface.v:273   assign apb_req_write = 1'b1;  // forwarder only ever writes
```

The command SPI is a 3-wire **input-only** bus (`cmd_sclk`, `cmd_csn`, `cmd_mosi`) — there is no
`cmd_miso`. The chip's only outputs are the three sensor-SPI pins (driven by `spi_master`) plus
`fault_flag_out`. So there is neither a master that can *issue* a read nor a pin on which read data
could *return*. Adding read-back would require a new output pin, a new pad assignment, and full
re-signoff of both the macro and the chip — it is not a firmware change.

**Latent bug to fix before any future read master is added:** `tmr_reg_bank` latches `prdata` on
`psel && !penable` (the APB SETUP phase), but `apb_arb2`'s grant is registered, so the slave sees
`psel` and `penable` rise on the *same* cycle and never observes SETUP. Reads through the arbiter
would return stale data. This is also a genuine AMBA deviation (a granted transfer skips its SETUP
phase), harmless today only because every transfer is a write and address/data are already
registered and stable.

### Recovering magnitude information on the bench: threshold bisection

The lost read-back is largely recoverable at board level, because `cfg_threshold` **is** writable
over the command SPI while `fault_flag_out` is observable:

1. Write a candidate threshold `T` over the command SPI.
2. Run one 512-sample block (~19.2 ms) and sample `fault_flag_out`.
3. `flag == 1` ⟹ some (axis, bin) magnitude `> T`; `flag == 0` ⟹ all magnitudes `≤ T`.
4. Binary-search `T` across the 32-bit range — **32 blocks (~0.6 s) resolves the peak magnitude
   exactly.**

This recovers the peak magnitude over all 9 (axis × bin) pairs, though not which pair produced it.
Per-bin isolation is still possible indirectly by zeroing the other two coefficients
(`cfg_c0/c1/c2`) so only the bin of interest accumulates energy.

Independent bench observability: `c_sclk`, `c_mosi` and `c_csn` are chip outputs, so the whole
sensor-SPI stream — boot configuration writes and the 48-bit burst reads — can be captured with a
logic analyser to confirm the front end is alive and correctly configured.

### Fault Attribution Example

If the X-axis exceeds threshold on frequency bin 0:
```
fault_flag_out   = 1
STATUS[0]        = 1
FAULT_MAG[31:0]  = <magnitude value>
FAULT_BIN[1:0]   = 2'b00  (bin 0)
FAULT_BIN[3:2]   = 2'b00  (X axis)
```

If the Z-axis exceeds threshold on frequency bin 2:
```
fault_flag_out   = 1
STATUS[0]        = 1
FAULT_MAG[31:0]  = <magnitude value>
FAULT_BIN[1:0]   = 2'b10  (bin 2)
FAULT_BIN[3:2]   = 2'b10  (Z axis)
```

## 5. Internal APB Register Map

The configuration and status interface is accessed via an internal APB bus (driven in silicon by a host-facing bridge outside `top.v`; driven directly in testbenches):

| Address | Register | Access | Description |
|---|---|---|---|
| 0x00 | CTRL | W | bit 0: `cfg_start` (W1P — write-1-to-pulse, enables `run_enable`); bit 1: `cfg_fault_clear` (W1P — clears sticky fault); bit 2: `cfg_stop` (W1P — disables `run_enable`) |
| 0x04 | CFG_C0 | R/W | [23:0] Goertzel coefficient for bin 0: `C0 = 2·cos(2π·f0/Fs)` in Q8.15 |
| 0x08 | CFG_C1 | R/W | [23:0] Goertzel coefficient for bin 1: `C1 = 2·cos(2π·f1/Fs)` in Q8.15 |
| 0x0C | CFG_C2 | R/W | [23:0] Goertzel coefficient for bin 2: `C2 = 2·cos(2π·f2/Fs)` in Q8.15 |
| 0x10 | CFG_THRESHOLD | R/W | [31:0] Fault detection threshold (unsigned integer, compared against `|X|²`) |
| 0x14 | STATUS | R | bit 0: `fault_flag` (sticky, cleared by CTRL[1]) |
| 0x18 | FAULT_MAG | R | [31:0] Magnitude that tripped the last fault (`fault_mag_latched`) |
| 0x1C | FAULT_BIN | R | [1:0] Frequency bin index (0–2); [3:2] Physical axis (0=X, 1=Y, 2=Z) |

### Coefficient Programming

The Goertzel coefficient for bin k tuned to frequency `f_k` (Hz) at sample rate `Fs = 26667 Hz` is:

```
C_k = 2 · cos(2π · f_k / Fs)

In Q8.15 fixed-point (24-bit signed, 1 sign bit, 8 integer bits, 15 fractional bits):
  C_k_q815 = round(C_k × 32768)

Example for common fault frequencies:
  f_k = 1 kHz  → C_k ≈ 1.9438  → C_k_q815 ≈ 63725  (0x0F8CD)
  f_k = 5 kHz  → C_k ≈ 0.7654  → C_k_q815 ≈ 25080  (0x061F8)
  f_k = 10 kHz → C_k ≈ -1.4142 → C_k_q815 ≈ -46340 (0xFF4AFC as signed 24-bit)
```

### Threshold Setting

`cfg_threshold` is compared against the computed magnitude `|X(f_k)|² = v1² + v2² - C·v1·v2`. The magnitude is a Q8.15 squared sum and grows with input amplitude. A typical threshold calibration:
1. Run with no fault stimulus → observe peak `FAULT_MAG` (noise floor magnitude)
2. Run with known fault amplitude → observe `FAULT_MAG` during fault
3. Set threshold between these two values

In the top-level testbench: threshold = 14, quiet floor ≈ 0, fault-tone magnitude >> 14.

## 6. Timing Characteristics

| Parameter | Value | Notes |
|---|---|---|
| System clock | 16 MHz | Signed-off macro clock (62.5 ns period) |
| SPI bit clock | `clk / 8` | 2 MHz at 16 MHz clk (`DIV_LOG2=3`) |
| Sensor ODR | 26.667 kHz | Fixed by IIS3DWB boot configuration |
| SPI transaction duration | ~56 µs (boot write: 8 SPI clocks) / ~28 µs (burst read: 8 + 48 = 56 SPI clocks at 2 MHz) | Depends on SPI clock rate |
| Sensor DRDY period | 37.5 µs | = 1/26.667 kHz |
| DRDY-to-data-ready latency | ~28 µs | SPI burst read time |
| Block processing time | 19.2 ms | 512 samples × 37.5 µs/sample |
| Fault detection latency | ≤ 19.2 ms | Within one block after fault starts |
| `fault_flag_out` timing | Synchronous to `clk` | No additional synchronizer needed on output |
